07장: 반응형 웹 디자인

기초

7장. 반응형 웹 디자인¶

학습 목표 - viewport 메타 태그로 반응형 기반을 설정할 수 있습니다 - 미디어 쿼리와 브레이크포인트로 화면별 스타일을 적용할 수 있습니다 - 모바일 우선 전략으로 레이아웃을 설계할 수 있습니다 - 유연한 단위와 반응형 이미지로 어떤 화면에서도 보기 좋은 페이지를 만들 수 있습니다

반응형 디자인과 뷰포트¶

도입¶

오늘날 웹 페이지는 스마트폰, 태블릿, 노트북, 대형 모니터 등 매우 다양한 화면에서 열립니다. 같은 페이지가 어느 기기에서나 읽기 좋게 보이려면 화면 크기에 맞춰 자동으로 레이아웃을 바꾸는 기술이 필요합니다. 이 절에서는 반응형 웹 디자인(Responsive Web Design)이 무엇인지, 그리고 그 출발점인 뷰포트(Viewport) 설정을 배웁니다.

핵심 개념 설명¶

반응형 디자인 (Responsive Design)¶

반응형 디자인(Responsive Design)은 하나의 HTML·CSS 코드로 다양한 화면 크기에 맞게 레이아웃이 자동 조정되는 방식입니다. 물이 담긴 그릇 모양에 따라 자연스럽게 형태를 바꾸듯, 콘텐츠가 화면 크기에 맞게 흘러가도록 설계합니다.

반응형 디자인이 등장하기 전에는 모바일용과 데스크톱용 사이트를 따로 만들었습니다. 두 벌의 코드를 유지하는 비용이 크고, 기기 종류가 다양해지면서 더 이상 이 방식이 현실적이지 않습니다.

뷰포트 (Viewport)¶

뷰포트(Viewport)는 브라우저가 웹 페이지를 실제로 보여 주는 영역입니다. 데스크톱에서는 브라우저 창 크기가 뷰포트이고, 모바일에서는 화면 크기가 뷰포트입니다.

문제는 스마트폰 브라우저가 기본적으로 페이지 너비를 980px 정도로 가정하여 렌더링하려 한다는 점입니다. 그 결과 모바일 화면에서 페이지가 축소되어 작게 보입니다. 이를 바로잡는 것이 viewport 메타 태그입니다.

viewport 메타 태그¶

<meta name="viewport"> 태그는 브라우저에게 "이 페이지의 너비를 기기 화면 너비에 맞춰라"고 지시합니다. 반응형 페이지라면 반드시 <head> 안에 포함해야 합니다.

<meta name="viewport" content="width=device-width, initial-scale=1">

<meta name="viewport" content="...">

항목 내용
설명 모바일 브라우저의 뷰포트 크기와 초기 배율을 설정합니다
content 속성 width=device-width: 뷰포트 너비를 기기 화면 너비로 설정
initial-scale=1: 초기 확대/축소 배율을 1(100%)로 고정
위치 <head> 안에 위치해야 합니다
사용 예시 <meta name="viewport" content="width=device-width, initial-scale=1">

물리 픽셀과 CSS 픽셀¶

스마트폰 화면은 실제 물리 픽셀(Physical Pixel) 밀도가 매우 높습니다. 예를 들어 iPhone의 레티나 디스플레이는 1인치당 픽셀 수가 데스크톱보다 2~3배 많습니다. 그래서 1개의 CSS 픽셀(CSS Pixel)이 실제로는 2~3개의 물리 픽셀로 렌더링됩니다. 이 비율을 장치 픽셀 비율(Device Pixel Ratio, DPR)이라고 합니다.

width=device-width를 설정하면 CSS 픽셀 기준으로 화면 너비가 결정되기 때문에 글자와 요소가 적절한 크기로 표시됩니다.

코드로 확인하기¶

viewport 메타 태그의 유무가 모바일 화면 렌더링에 어떤 차이를 만드는지 확인합니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <!-- viewport 메타 태그를 포함해야 모바일에서 올바르게 표시됩니다 -->
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>뷰포트 예제</title>
  <style>
    body {
      font-family: sans-serif;
      margin: 0;
      padding: 16px;
      background-color: #f0f4ff;
    }

    .box {
      background-color: #4f46e5;
      color: white;
      padding: 20px;
      border-radius: 8px;
      text-align: center;
      font-size: 1.2rem;
    }
  </style>
</head>
<body>
  <div class="box">
    이 박스는 화면 너비에 맞춰 표시됩니다.
  </div>
</body>
</html>

절 요약¶

  • 반응형 디자인(Responsive Design)은 하나의 코드로 모든 화면 크기를 지원합니다
  • 뷰포트(Viewport)는 브라우저가 페이지를 렌더링하는 실제 영역입니다
  • <meta name="viewport" content="width=device-width, initial-scale=1">은 모든 반응형 페이지의 필수 설정입니다

미디어 쿼리와 브레이크포인트¶

도입¶

뷰포트 설정만으로는 부족합니다. 모바일에서는 1열로, 태블릿에서는 2열로, 데스크톱에서는 3열로 레이아웃을 바꾸려면 화면 크기 조건에 따라 서로 다른 CSS를 적용하는 방법이 필요합니다. 이것이 바로 미디어 쿼리(Media Query)입니다.

핵심 개념 설명¶

미디어 쿼리 (Media Query)¶

미디어 쿼리(Media Query)는 @media 규칙을 사용하여 특정 조건(화면 너비, 방향, 해상도 등)을 만족할 때만 CSS를 적용하는 기능입니다. 옷장을 계절에 따라 다르게 정리하듯, 화면 크기에 따라 다른 스타일을 입힙니다.

@media (조건) {
  /* 조건을 만족할 때만 적용되는 CSS */
}

가장 많이 사용하는 조건은 화면 너비(width)입니다.

/* 화면 너비가 768px 이상일 때 */
@media (min-width: 768px) {
  .container {
    display: grid;
    grid-template-columns: 1fr 2fr;
  }
}

@media (조건) { ... }

항목 내용
설명 미디어 특성 조건에 따라 CSS 블록을 조건부 적용합니다
주요 조건 min-width: Xpx — 화면 너비가 X픽셀 이상일 때
max-width: Xpx — 화면 너비가 X픽셀 이하일 때
screen — 화면(스크린) 미디어 타입에만 적용
AND 조합 @media screen and (min-width: 768px)
사용 예시 @media (min-width: 600px) { .col { flex: 1; } }

브레이크포인트 (Breakpoint)¶

브레이크포인트(Breakpoint)는 레이아웃이 바뀌는 화면 너비 기준점입니다. 미디어 쿼리를 작성할 때 어떤 너비에서 레이아웃을 변경할지 정하는 것입니다.

팁: 브레이크포인트는 특정 기기 해상도(예: iPhone = 375px)에 맞추는 것이 아니라, 콘텐츠가 보기 불편해지는 지점을 기준으로 정하는 것이 좋습니다. 기기는 계속 바뀌지만 콘텐츠 흐름은 일관됩니다.

일반적으로 많이 사용하는 브레이크포인트는 다음과 같습니다.

구분 화면 너비 주요 기기
모바일 ~ 767px 스마트폰 세로 방향
태블릿 768px ~ 1023px 태블릿, 스마트폰 가로 방향
데스크톱 1024px ~ 노트북, 모니터

코드로 확인하기¶

화면 너비에 따라 카드 레이아웃이 1열 → 2열 → 3열로 바뀌는 예제입니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>미디어 쿼리 예제</title>
  <style>
    /* 기본 스타일 (모바일: 1열) */
    body {
      font-family: sans-serif;
      margin: 0;
      padding: 16px;
      background-color: #f8f9fa;
    }

    .card-grid {
      display: grid;
      grid-template-columns: 1fr;  /* 모바일: 1열 */
      gap: 16px;
    }

    .card {
      background-color: white;
      border: 1px solid #dee2e6;
      border-radius: 8px;
      padding: 20px;
      text-align: center;
    }

    .card h3 {
      margin: 0 0 8px;
      color: #343a40;
    }

    .card p {
      margin: 0;
      color: #6c757d;
      font-size: 0.9rem;
    }

    /* 태블릿: 2열 */
    @media (min-width: 768px) {
      .card-grid {
        grid-template-columns: repeat(2, 1fr);
      }
    }

    /* 데스크톱: 3열 */
    @media (min-width: 1024px) {
      .card-grid {
        grid-template-columns: repeat(3, 1fr);
      }
    }
  </style>
</head>
<body>
  <h1>카드 갤러리</h1>
  <div class="card-grid">
    <div class="card">

and, not, only 조건 조합하기¶

미디어 쿼리는 여러 조건을 and로 결합하거나 not으로 부정할 수 있습니다.

/* 화면 미디어이고 너비가 768px 이상 1200px 이하인 경우 */
@media screen and (min-width: 768px) and (max-width: 1199px) {
  .layout {
    padding: 0 24px;
  }
}

/* 인쇄 시 불필요한 요소 숨기기 */
@media print {
  nav,
  footer {
    display: none;
  }
}

절 요약¶

  • 미디어 쿼리(Media Query)는 @media 규칙으로 화면 크기 조건에 따라 CSS를 조건부 적용합니다
  • 브레이크포인트(Breakpoint)는 레이아웃이 바뀌는 화면 너비 기준점으로, 콘텐츠가 불편해지는 지점에서 정합니다
  • min-width는 모바일 우선 방향, max-width는 데스크톱 우선 방향으로 사용합니다

모바일 우선 접근법¶

도입¶

미디어 쿼리를 min-width로 쓰느냐 max-width로 쓰느냐의 차이가 왜 중요한 것일까요? 이 선택이 바로 모바일 우선(Mobile-first) 전략과 데스크톱 우선(Desktop-first) 전략을 나눕니다. 이 절에서는 모바일 우선 접근법이 무엇인지, 왜 권장되는지, 그리고 실제로 어떻게 코드를 구성하는지 배웁니다.

핵심 개념 설명¶

모바일 우선이란¶

모바일 우선(Mobile-first)은 기본 CSS를 모바일 화면에 맞게 먼저 작성하고, 화면이 커질수록 min-width 미디어 쿼리로 스타일을 확장하는 설계 전략입니다. 작은 도시락에 핵심 반찬을 먼저 담고, 큰 도시락일 때 반찬을 추가하는 것과 같습니다.

데스크톱 우선은 반대입니다. 큰 화면을 기본으로 작성하고 max-width로 점점 줄여 나갑니다. 직관적으로 보이지만 실제로는 불필요한 CSS를 덮어 쓰는 일이 많아 코드가 복잡해집니다.

두 전략 비교¶

/* 데스크톱 우선 방식 (max-width 사용) */
.nav {
  display: flex;        /* 데스크톱 기본 */
  flex-direction: row;
}

@media (max-width: 767px) {
  .nav {
    flex-direction: column;  /* 모바일에서 덮어 씁니다 */
  }
}

/* 모바일 우선 방식 (min-width 사용) */
.nav {
  display: flex;
  flex-direction: column;  /* 모바일 기본 */
}

@media (min-width: 768px) {
  .nav {
    flex-direction: row;   /* 태블릿 이상에서 확장합니다 */
  }
}

두 코드의 결과는 동일하지만 모바일 우선 방식이 더 단순합니다. 기본 스타일이 작은 화면에서 항상 올바르게 보이고, 큰 화면에서만 추가 스타일이 얹히기 때문입니다.

점진적 향상 전략¶

모바일 우선은 점진적 향상(Progressive Enhancement)이라는 개념과 연결됩니다. 핵심 기능을 먼저 완벽하게 만들고, 더 큰 화면이나 더 나은 환경에서 기능을 추가해 나가는 전략입니다. 반대 개념인 우아한 저하(Graceful Degradation)는 최고 환경을 기준으로 만든 뒤 낮은 환경에서 어떻게 줄일지 고민합니다.

절 요약¶

  • 모바일 우선(Mobile-first)은 기본 스타일을 모바일에 맞추고, min-width로 큰 화면을 확장하는 전략입니다
  • 데스크톱 우선보다 코드가 단순하고 불필요한 CSS 덮어쓰기가 줄어듭니다
  • 점진적 향상(Progressive Enhancement)은 핵심 기능을 먼저 완성하고 더 좋은 환경에서 기능을 추가하는 방향입니다

유연한 단위와 레이아웃¶

도입¶

고정 픽셀(px) 값만 사용하면 모든 화면 크기에 완벽히 맞추기 어렵습니다. 예를 들어 데스크톱에서 font-size: 24px로 지정한 제목이 작은 모바일 화면에서는 너무 크게 보일 수 있습니다. 이 절에서는 화면 크기에 따라 자동으로 조정되는 유연한 단위(Flexible Units)와 이를 활용한 레이아웃 기법을 배웁니다.

핵심 개념 설명¶

퍼센트(%)와 뷰포트 단위(vw, vh)¶

퍼센트(%)는 부모 요소의 크기를 기준으로 비율로 크기를 지정합니다.

뷰포트 단위(Viewport Units)는 브라우저 화면 크기를 기준으로 하는 단위입니다.

단위 기준 예시
% 부모 요소의 너비 또는 높이 width: 50% — 부모 너비의 절반
vw 뷰포트 너비의 1/100 width: 100vw — 화면 너비 전체
vh 뷰포트 높이의 1/100 height: 100vh — 화면 높이 전체
vmin vw와 vh 중 작은 값 정사각형 요소에 유용
vmax vw와 vh 중 큰 값 화면 방향에 무관한 크기 지정

주의: 100vw는 스크롤바 너비를 포함하므로 수평 스크롤이 생길 수 있습니다. 레이아웃 너비에는 100%를 사용하고, 전체 화면 배경처럼 스크롤바가 없는 상황에서 100vw를 사용합니다.

clamp()로 반응형 글자 크기 만들기¶

clamp(최솟값, 기준값, 최댓값) 함수는 값이 최솟값과 최댓값 사이에 있도록 자동으로 제한합니다. 미디어 쿼리 없이도 반응형 글자 크기를 만들 수 있어 매우 유용합니다.

h1 {
  font-size: clamp(1.5rem, 4vw, 3rem);
  /* 최소 1.5rem, 화면 너비의 4%, 최대 3rem */
}

화면이 작을 때는 1.5rem, 화면이 커질수록 뷰포트 너비의 4%로 늘다가 3rem을 넘지 않습니다.

clamp(min, val, max)

항목 내용
설명 값을 최솟값과 최댓값 사이로 제한합니다. max(min, min(val, max))와 동일합니다
매개변수 min: 허용 최솟값
val: 기준값 (보통 vw 기반 유연한 값)
max: 허용 최댓값
반환값 세 값 중 중간 크기의 값
사용 예시 font-size: clamp(1rem, 2.5vw, 2rem)

코드로 확인하기¶

퍼센트, vw/vh, clamp()를 사용한 유연한 레이아웃입니다. 화면 크기를 바꾸면 글자 크기와 여백이 자동으로 조정됩니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>유연한 단위 예제</title>
  <style>
    * {
      box-sizing: border-box;
      margin: 0;
      padding: 0;
    }

    body {
      font-family: sans-serif;
      /* vw 기반 패딩으로 화면 크기에 따라 여백이 늘어납니다 */
      padding: 0 clamp(16px, 4vw, 64px);
    }

    /* 히어로 섹션: 화면 전체 높이를 차지합니다 */
    .hero {
      min-height: 100vh;
      display: flex;
      flex-direction: column;
      justify-content: center;
      background: linear-gradient(135deg, #667eea, #764ba2);
      color: white;
      text-align: center;
    }

    .hero__title {
      font-size: clamp(2rem, 6vw, 5rem);
      line-height: 1.2;
      margin-bottom: clamp(12px, 2vw, 24px);
    }

    /* clamp()로 반응형 부제목 크기 */
    .hero__subtitle {
      font-size: clamp(1rem, 2.5vw, 1.5rem);
      opacity: 0.85;
    }

    /* 콘텐츠 섹션: 최대 너비 제한 */
    .content {
      max-width: 800px;        /* 지나치게 넓어지지 않도록 제한 */
      margin: 48px auto;       /* 가운데 정렬 */
      display: grid;
      gap: 24px;
    }

    .feature {
      background-color: #f8f9fa;
      border-radius: 8px;
      padding: clamp(16px, 3vw, 32px);

      }
    }

min(), max() 함수¶

clamp()와 함께 min()과 max() 함수도 유연한 레이아웃에 활용됩니다.

/* 부모 너비의 80%이지만 400px을 넘지 않는 너비 */
.card {
  width: min(80%, 400px);
}

/* 최소 200px, 또는 부모의 50% 중 더 큰 값 */
.sidebar {
  width: max(200px, 50%);
}

팁: width: min(100%, 600px)는 max-width: 600px; width: 100%;와 동일한 효과입니다. 코드를 한 줄로 줄일 수 있습니다.

절 요약¶

  • %는 부모 기준, vw/vh는 뷰포트 기준의 유연한 단위입니다
  • clamp(min, val, max)는 미디어 쿼리 없이 반응형 크기를 만드는 강력한 도구입니다
  • max-width로 넓은 화면에서의 지나친 확장을 방지하고, margin: auto로 가운데 정렬합니다

반응형 이미지와 미디어¶

도입¶

레이아웃이 반응형이 되었다면 이제 이미지도 화면에 맞게 조정해야 합니다. 이미지가 컨테이너보다 크면 가로 스크롤이 생기고, 고해상도 이미지를 작은 모바일 화면에 그대로 내려보내면 불필요한 데이터를 낭비합니다. 이 절에서는 반응형 이미지를 다루는 방법을 배웁니다.

핵심 개념 설명¶

max-width: 100%로 이미지 넘침 방지하기¶

가장 단순한 반응형 이미지 기법입니다. max-width: 100%를 이미지에 적용하면 컨테이너보다 커지지 않으면서도 본래 크기보다 강제로 늘어나지 않습니다.

img {
  max-width: 100%;
  height: auto;   /* 비율 유지 */
  display: block;
}

베스트 프랙티스: max-width: 100%; height: auto;는 모든 이미지의 기본 스타일로 전역에 적용하는 것이 좋습니다. 이미지가 실수로 컨테이너를 넘어가는 문제를 예방합니다.

srcset과 sizes로 화면별 이미지 제공하기¶

max-width: 100%는 이미지 크기를 CSS로 조정할 뿐, 큰 이미지 파일이 전송되는 것은 막지 못합니다. 모바일 사용자에게 3000px 이미지를 내려보내면 데이터가 낭비됩니다.

srcset 속성은 브라우저에게 서로 다른 크기의 이미지 파일 목록과 각 파일의 너비를 알려줍니다. 브라우저가 화면 크기와 해상도에 맞는 최적의 이미지를 자동으로 선택합니다.

sizes 속성은 이미지가 실제로 화면에서 얼마나 넓게 표시될지를 브라우저에게 힌트로 알려줍니다.

<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1200.jpg 1200w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="풍경 사진"
>

<img srcset="..." sizes="...">

항목 내용
설명 화면 크기와 해상도에 따라 브라우저가 최적의 이미지를 자동 선택합니다
srcset 파일경로 너비w 형식으로 이미지 후보 목록을 지정합니다 (예: small.jpg 400w, large.jpg 800w)
sizes 미디어 조건과 이미지 표시 너비를 쌍으로 지정합니다 (예: (max-width: 600px) 100vw, 50vw)
src srcset을 지원하지 않는 브라우저를 위한 기본 이미지 경로입니다
사용 예시 모바일에서 작은 파일, 고해상도 데스크톱에서 큰 파일을 자동 선택합니다

picture 요소로 아트 디렉션하기¶

srcset/sizes는 같은 이미지의 크기를 바꿀 뿐입니다. 모바일에서는 인물 클로즈업, 데스크톱에서는 배경이 넓게 보이는 원본처럼 이미지 자체를 바꾸고 싶을 때는 <picture> 요소를 사용합니다. 이를 아트 디렉션(Art Direction)이라고 합니다.

<picture>
  <!-- 768px 이상: 가로로 넓은 이미지 -->
  <source media="(min-width: 768px)" srcset="hero-wide.jpg">
  <!-- 그 외(모바일 기본): 세로 비율 이미지 -->
  <img src="hero-mobile.jpg" alt="히어로 이미지">
</picture>

<picture>, <source media="..." srcset="...">

항목 내용
설명 미디어 조건에 따라 완전히 다른 이미지를 제공하는 아트 디렉션을 구현합니다
source media 미디어 조건이 일치하면 해당 srcset 이미지를 사용합니다
source srcset 해당 조건에서 사용할 이미지 파일을 지정합니다
img (필수) <picture> 안에 반드시 <img>가 있어야 합니다. 어떤 source도 맞지 않을 때의 기본 이미지이며 alt도 여기 작성합니다
사용 예시 모바일과 데스크톱에서 완전히 다른 구도의 이미지를 보여줄 때 사용합니다

절 요약¶

  • max-width: 100%; height: auto;를 모든 이미지의 기본 스타일로 적용합니다
  • srcset과 sizes로 브라우저가 화면 크기에 맞는 이미지 파일을 자동 선택하도록 합니다
  • <picture> 요소는 화면 크기에 따라 완전히 다른 이미지를 보여주는 아트 디렉션에 사용합니다

FAQ¶

Q1: viewport 메타 태그 없이도 미디어 쿼리가 동작하나요?

동작하기는 하지만 의도한 대로 동작하지 않습니다. viewport 태그가 없으면 모바일 브라우저가 페이지 너비를 980px로 가정하여 렌더링합니다. 그 결과 모바일 화면에서 min-width: 768px 조건이 이미 참이 되어 태블릿 스타일이 적용되는 식으로 미디어 쿼리가 엉뚱하게 동작합니다. 반드시 <meta name="viewport" content="width=device-width, initial-scale=1">을 포함합니다.

Q2: 브레이크포인트를 몇 개나 사용하는 것이 좋나요?

정해진 답은 없지만, 일반적으로 2~3개(모바일/태블릿/데스크톱)로 시작하는 것을 권장합니다. 브레이크포인트가 너무 많으면 유지보수가 어렵고, 코드가 복잡해집니다. 특정 기기 해상도가 아니라 콘텐츠가 보기 불편해지는 시점에서 브레이크포인트를 추가하는 방식으로 접근합니다.

Q3: em 단위로 미디어 쿼리를 작성하는 것이 더 좋다고 들었는데, 맞나요?

미디어 쿼리 조건에 em을 사용하면 사용자가 브라우저 기본 글자 크기를 키웠을 때도 올바르게 반응한다는 장점이 있습니다. 예를 들어 @media (min-width: 48em)은 기본 설정(16px)에서 768px과 같습니다. 다만 입문 단계에서는 이해하기 쉬운 px 단위를 먼저 사용하고, 접근성을 더 깊이 고려할 때 em으로 전환해도 충분합니다.

Q4: srcset을 쓰면 항상 작은 이미지를 선택하나요?

그렇지 않습니다. 브라우저는 화면 너비뿐만 아니라 장치 픽셀 비율(DPR)도 고려합니다. 레티나 디스플레이(DPR=2)의 작은 화면에서는 실제로는 큰 이미지를 선택할 수 있습니다. 또한 브라우저가 이미지를 한 번 받아 캐시했다면 더 작은 이미지가 있어도 캐시된 것을 재사용합니다. srcset은 브라우저에게 "이런 선택지가 있다"고 알려 주는 것이고, 최종 선택은 브라우저가 합니다.

장 요약¶

이번 장에서는 다양한 화면 크기에서 보기 좋은 페이지를 만드는 반응형 웹 디자인의 핵심 기술을 배웠습니다. 모든 반응형 페이지의 출발점은 viewport 메타 태그이며, @media 미디어 쿼리로 화면 크기 조건에 따라 서로 다른 CSS를 적용합니다. 모바일 우선 전략으로 min-width 기반 브레이크포인트를 구성하면 코드가 단순해지고 유지보수가 쉬워집니다. clamp(), vw/vh, % 같은 유연한 단위를 활용하면 미디어 쿼리 없이도 자동으로 조정되는 요소를 만들 수 있으며, srcset과 <picture> 요소로 이미지도 화면 크기에 최적화할 수 있습니다.

핵심 키워드¶

뷰포트(Viewport), 미디어 쿼리(Media Query), 브레이크포인트(Breakpoint), 모바일 우선(Mobile-first), clamp(), srcset, <picture>
