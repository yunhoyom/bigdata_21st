입문

3장. HTML 심화: 링크, 이미지, 표, 폼¶

학습 목표 - 절대 경로와 상대 경로를 구분하여 링크를 작성할 수 있습니다 - alt 속성을 갖춘 이미지와 멀티미디어를 삽입할 수 있습니다 - 표를 사용하여 데이터를 구조적으로 정리할 수 있습니다 - label로 연결된 접근성 있는 입력 폼을 만들고 기본 유효성 검사를 적용할 수 있습니다

3.1 하이퍼링크로 페이지 연결하기¶

도입¶

웹을 웹답게 만드는 가장 핵심 기능은 하이퍼링크(Hyperlink)입니다. 하이퍼링크 덕분에 우리는 한 페이지에서 다른 페이지로, 다른 사이트로, 심지어 같은 페이지 안의 다른 위치로 이동할 수 있습니다. 링크가 없다면 웹은 그냥 독립된 문서들의 모음일 뿐입니다. 이 절에서는 링크를 만드는 <a> 태그와 경로 작성법을 익힙니다.

핵심 개념 설명¶

앵커 태그(Anchor Tag)와 href 속성¶

앵커 태그(Anchor Tag)는 <a> 태그로 표현합니다. 앵커(anchor)는 '닻'을 뜻하며, 어떤 위치를 붙잡아 연결한다는 의미입니다. 링크를 만들려면 href 속성에 이동할 주소를 적으면 됩니다.

<a href="https://www.naver.com">네이버로 이동</a>

href는 "Hypertext REFerence"의 줄임말입니다. 여는 태그 <a href="..."> 와 닫는 태그 </a> 사이에 링크 텍스트를 넣으면, 브라우저가 밑줄이 그어진 파란 텍스트로 표시해 줍니다.

팁: 링크 텍스트는 "여기를 클릭"처럼 모호하게 쓰지 말고, "네이버 메인 페이지"처럼 목적지를 명확히 표현하세요. 스크린 리더 사용자와 검색엔진 모두에게 더 명확한 정보를 전달합니다.

절대 경로와 상대 경로(Absolute and Relative Paths)¶

경로(Path)는 파일의 위치를 나타내는 주소입니다. 절대 경로(Absolute Path)와 상대 경로(Relative Path) 두 가지 방식이 있습니다.

절대 경로는 도메인(또는 루트 폴더)부터의 완전한 주소입니다. 마치 "서울시 강남구 ○○로 1번지"처럼 어디에서 출발해도 정확히 찾아갈 수 있는 완전한 주소입니다.

  • https://www.example.com/about.html — 외부 사이트의 완전한 URL
  • /images/logo.png — 사이트 루트(/)부터 시작하는 경로

상대 경로는 현재 파일 위치를 기준으로 상대적으로 표현한 경로입니다. "여기서 두 블록 직진, 왼쪽으로 꺾기"처럼 현재 위치를 알아야 이해할 수 있는 안내 방식입니다.

표기 의미 예
파일명.html 현재 폴더 안의 파일 about.html
./파일명.html 현재 폴더 (./은 생략 가능) ./about.html
폴더명/파일명.html 현재 폴더의 하위 폴더 pages/contact.html
../파일명.html 상위 폴더로 이동 후 파일 ../index.html
../../파일명.html 두 단계 상위 폴더 ../../index.html

코드로 확인하기¶

다음 코드는 절대 경로와 상대 경로를 모두 사용하여 다양한 링크를 만드는 방법을 보여줍니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>하이퍼링크 예제</title>
</head>
<body>
  <h1>다양한 링크 예제</h1>

  <!-- 외부 사이트로 이동하는 절대 경로 링크 -->
  <p>
    <a href="https://www.naver.com">절대 경로: 네이버 방문하기</a>
  </p>

  <!-- 같은 폴더의 다른 파일로 이동 (상대 경로) -->
  <p>
    <a href="about.html">상대 경로: 소개 페이지로 이동</a>
  </p>

  <!-- 하위 폴더의 파일 -->
  <p>
    <a href="pages/contact.html">상대 경로: 연락처 페이지</a>
  </p>

  <!-- 상위 폴더의 파일 -->
  <p>
    <a href="../index.html">상대 경로: 상위 폴더의 메인 페이지</a>
  </p>
</body>
</html>

브라우저에서 열면 각 문장 아래 밑줄이 그어진 파란 링크 텍스트가 표시됩니다. about.html이나 pages/contact.html이 실제로 없는 경우 클릭하면 "404 Not Found" 오류가 납니다.

줄별 코드 설명

줄 코드 설명
9 <a href="https://www.naver.com"> 절대 경로로 외부 사이트 연결. 전체 URL을 그대로 씁니다
14 <a href="about.html"> 현재 파일과 같은 폴더에 있는 about.html로 연결하는 상대 경로
19 <a href="pages/contact.html"> 현재 폴더 안의 pages 하위 폴더에 있는 파일 연결
24 <a href="../index.html"> ../는 상위 폴더를 의미. 한 단계 위 폴더의 index.html에 연결

새 탭으로 열기와 보안 주의¶

외부 사이트로 링크할 때 새 탭에서 열리게 하려면 target="_blank" 속성을 추가합니다.

<a href="https://www.naver.com" target="_blank" rel="noopener noreferrer">
  네이버 (새 탭)
</a>

줄별 코드 설명

줄 코드 설명
1 target="_blank" 링크를 새 탭(또는 새 창)에서 엽니다
1 rel="noopener noreferrer" 보안 속성. noopener는 새 탭이 원래 페이지를 제어하지 못하게 막고, noreferrer는 출처 정보 전송을 차단합니다

주의: target="_blank"만 쓰고 rel="noopener noreferrer"를 빠뜨리면, 열린 새 탭이 window.opener를 통해 원래 페이지를 조작할 수 있는 보안 취약점이 생깁니다. 외부 링크에는 항상 두 속성을 함께 씁니다.

페이지 내부 앵커 이동¶

같은 페이지 안에서 특정 위치로 이동하는 링크도 만들 수 있습니다. 목적지 요소에 id 속성을 달고, href에 #아이디를 씁니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>내부 앵커 예제</title>
</head>
<body>
  <!-- 목차 링크 -->
  <nav>
    <a href="#section1">1장으로 이동</a>
    <a href="#section2">2장으로 이동</a>
  </nav>

  <!-- 목적지 위치 -->
  <section id="section1">
    <h2>1장: 소개</h2>
    <p>긴 내용...</p>
  </section>

  <section id="section2">
    <h2>2장: 본론</h2>
    <p>더 긴 내용...</p>
  </section>
</body>
</html>

줄별 코드 설명

줄 코드 설명
9 <a href="#section1"> #으로 시작하는 href는 같은 페이지의 id를 가리킵니다
15 <section id="section1"> href="#section1"이 이 요소로 스크롤하여 이동합니다

베스트 프랙티스: 긴 페이지에서 "맨 위로 이동" 버튼을 만들 때도 <a href="#top">맨 위로</a> 처럼 #top을 사용하거나, 페이지 최상단 요소에 id="top"을 붙이는 방식을 씁니다.

절 요약¶

  • <a href="주소">링크 텍스트</a> 형태로 하이퍼링크를 만듭니다
  • 절대 경로는 도메인이나 루트(/)부터의 완전한 주소, 상대 경로는 현재 파일 기준의 위치입니다
  • 외부 링크에 target="_blank" 사용 시 반드시 rel="noopener noreferrer"를 함께 씁니다
  • 같은 페이지 내 이동은 href="#아이디" 형식으로 구현합니다

3.2 이미지와 멀티미디어¶

도입¶

이미지와 영상은 텍스트만으로는 전달하기 어려운 정보를 효과적으로 전달합니다. 하지만 시각 장애가 있는 사용자나 이미지 로드에 실패한 상황에서도 콘텐츠의 의미가 전달되어야 합니다. 이 절에서는 이미지와 멀티미디어를 삽입하는 방법, 그리고 접근성(Accessibility)을 위한 alt 속성을 함께 배웁니다.

핵심 개념 설명¶

이미지 태그(Image Tag)¶

<img> 태그는 웹 페이지에 이미지를 삽입합니다. <img>는 닫는 태그가 없는 빈 요소(Void Element)입니다.

<img src="" alt="">

항목 내용
설명 웹 페이지에 이미지를 삽입하는 HTML 요소
주요 속성 src (필수): 이미지 파일 경로 또는 URL
alt (필수): 이미지를 대체하는 텍스트 설명
width: 이미지 너비(px 또는 숫자)
height: 이미지 높이
loading="lazy": 지연 로딩(화면에 보일 때만 로드)
빈 요소 닫는 태그 없음. <img ... /> 또는 <img ...> 모두 유효

대체 텍스트(Alternative Text)와 접근성¶

대체 텍스트(alt 속성)는 이미지를 대신 설명하는 텍스트입니다. 라디오 진행자가 그림을 보지 못하는 청취자에게 그림 내용을 말로 설명해 주는 것과 같습니다.

alt 속성이 중요한 세 가지 이유는 다음과 같습니다.

  1. 접근성: 시각 장애가 있는 사용자가 쓰는 스크린 리더(Screen Reader)가 alt 텍스트를 읽어 이미지 내용을 알립니다
  2. 이미지 로드 실패: 네트워크 문제나 경로 오류로 이미지가 로드되지 않을 때 alt 텍스트가 대신 표시됩니다
  3. SEO: 검색엔진은 이미지를 직접 보지 못하고 alt 텍스트를 통해 이미지 내용을 파악합니다

alt 텍스트 작성 규칙은 다음과 같습니다.

상황 올바른 alt 잘못된 alt
의미 있는 이미지 alt="빨간 사과 세 개가 나무 바구니에 담겨 있는 사진" alt="이미지", alt="사진"
로고/아이콘 alt="네이버 로고" alt="" (아이콘이지만 의미 있을 때)
장식용 이미지 alt="" (빈 문자열, 스크린 리더가 건너뜀) alt 속성 자체를 생략
버튼 이미지 alt="검색" alt="btn_search.png"

주의: alt 속성을 완전히 생략하면 스크린 리더가 파일명(btn_search.png 등)을 읽어 버립니다. 장식용 이미지라면 alt=""(빈 문자열)을 명시적으로 써야 합니다.

코드로 확인하기¶

다음 코드는 이미지를 올바르게 삽입하는 다양한 방법을 보여줍니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>이미지 예제</title>
</head>
<body>
  <h1>이미지 삽입 예제</h1>

  <!-- 기본 이미지 삽입 (상대 경로) -->
  <img
    src="images/apple.jpg"
    alt="빨간 사과 세 개가 바구니에 담겨 있는 사진"
    width="300"
    height="200"
  >

  <!-- 외부 URL 이미지 -->
  <img
    src="https://via.placeholder.com/400x200"
    alt="400x200 크기의 회색 플레이스홀더 이미지"
  >

  <!-- 장식용 이미지 (스크린 리더가 건너뜀) -->
  <img src="images/divider.png" alt="">

  <!-- 지연 로딩 (스크롤해서 보이는 시점에 로드) -->
  <img
    src="images/landscape.jpg"
    alt="산과 호수가 있는 풍경 사진"
    loading="lazy"
  >
</body>
</html>

브라우저에서 열면 이미지가 표시됩니다. 이미지 파일이 없으면 alt 텍스트가 대신 나타납니다.

줄별 코드 설명

줄 코드 설명
11~16 <img src="images/apple.jpg" alt="..."> 가장 기본적인 이미지 삽입. src에 경로, alt에 설명을 씁니다
12 src="images/apple.jpg" 현재 HTML 파일 기준으로 images 하위 폴더의 apple.jpg 파일
13 alt="빨간 사과 세 개..." 이미지 내용을 구체적으로 묘사하는 대체 텍스트
14~15 width="300" height="200" 이미지 크기를 픽셀로 지정. 레이아웃 깜빡임(CLS) 방지에도 도움
23 alt="" 빈 alt로 장식용 이미지임을 명시. 스크린 리더가 이 이미지를 무시합니다
26~30 loading="lazy" 뷰포트에 가까워질 때 로드. 초기 페이지 속도 향상에 유리합니다

오디오(audio)와 비디오(video)로 멀티미디어 넣기¶

HTML5부터는 <audio>와 <video> 태그로 플러그인 없이 미디어를 재생할 수 있습니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>멀티미디어 예제</title>
</head>
<body>
  <h1>멀티미디어 예제</h1>

  <!-- 오디오 플레이어 -->
  <h2>배경 음악</h2>
  <audio controls>
    <source src="audio/bgm.mp3" type="audio/mpeg">
    <source src="audio/bgm.ogg" type="audio/ogg">
    <p>이 브라우저는 오디오 재생을 지원하지 않습니다.
      <a href="audio/bgm.mp3">파일을 직접 다운로드</a>하세요.
    </p>
  </audio>

  <!-- 비디오 플레이어 -->
  <h2>소개 영상</h2>
  <video controls width="640" height="360">
    <source src="video/intro.mp4" type="video/mp4">
    <source src="video/intro.webm" type="video/webm">
    <p>이 브라우저는 비디오 재생을 지원하지 않습니다.
      <a href="video/intro.mp4">파일을 직접 다운로드</a>하세요.
    </p>
  </video>
</body>
</html>

줄별 코드 설명

줄 코드 설명
12 <audio controls> controls를 쓰면 재생/일시정지/볼륨 컨트롤 바가 표시됩니다
13~14 <source src="..." type="..."> 여러 포맷을 나열하면 브라우저가 지원 가능한 첫 번째 포맷을 선택합니다
15~17 <p>이 브라우저는 ...</p> <audio> 안의 텍스트는 미디어를 지원하지 않는 브라우저에서만 표시됩니다
22 <video controls width="640" height="360"> 비디오 크기는 width/height로 지정합니다. 비율 유지를 위해 둘 다 명시하는 것이 좋습니다

베스트 프랙티스: <video>에 자막을 제공하려면 <track> 요소를 추가하세요. <track kind="subtitles" src="subtitles.vtt" srclang="ko" label="한국어">처럼 사용합니다. 이는 청각 장애인 접근성을 위한 중요한 수단입니다.

절 요약¶

  • <img src="..." alt="..."> 형태로 이미지를 삽입합니다
  • 의미 있는 이미지에는 내용을 구체적으로 설명하는 alt 텍스트가 반드시 필요합니다
  • 장식용 이미지는 alt=""(빈 문자열)을 명시하여 스크린 리더가 건너뛰게 합니다
  • <audio>와 <video>는 controls 속성과 여러 <source>를 함께 사용합니다

3.3 표로 데이터 정리하기¶

도입¶

HTML 표(Table)는 시간표, 가격표, 성적표처럼 행(Row)과 열(Column)로 이루어진 2차원 데이터를 표현할 때 사용합니다. 표는 데이터를 보기 쉽게 정리해 주는 강력한 도구이지만, 레이아웃 목적으로 남용하면 안 됩니다. 레이아웃은 CSS Flexbox와 Grid로 해결하는 것이 올바른 방법입니다.

핵심 개념 설명¶

표의 기본 구조¶

HTML 표는 다음 태그들로 구성됩니다.

표 관련 핵심 태그

태그 역할
<table> 표 전체를 감싸는 컨테이너
<tr> 테이블 행(Table Row). 표의 한 줄
<td> 데이터 셀(Table Data). 일반 데이터가 들어가는 칸
<th> 헤더 셀(Table Header). 제목 역할을 하는 칸. 기본적으로 굵고 가운데 정렬
<thead> 표 머리 영역. 헤더 행 그룹
<tbody> 표 본문 영역. 데이터 행 그룹
<tfoot> 표 꼬리 영역. 합계 등 요약 행 그룹
<caption> 표의 제목/설명. <table> 바로 다음에 위치

팁: <thead>, <tbody>, <tfoot>을 나누면 표의 의미 구조가 명확해지고, 스크린 리더와 검색엔진이 표를 더 잘 이해합니다. 또한 CSS로 각 영역을 따로 스타일링하기도 쉬워집니다.

코드로 확인하기 — 기본 표 만들기¶

셀 병합하기: colspan과 rowspan¶

여러 칸을 합쳐 하나의 셀로 만들 수 있습니다.

  • colspan="숫자": 가로로 몇 칸을 합칠지 (열 병합)
  • rowspan="숫자": 세로로 몇 칸을 합칠지 (행 병합)
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>셀 병합 예제</title>
  <style>
    table { border-collapse: collapse; }
    th, td { border: 1px solid #999; padding: 8px 12px; text-align: center; }
    th { background-color: #d0e8ff; }
  </style>
</head>
<body>
  <h1>시간표 예제 (셀 병합)</h1>

  <table>
    <caption>1학년 1반 시간표</caption>
    <thead>
      <tr>
        <th>교시</th>
        <th>월</th>
        <th>화</th>
        <th>수</th>
        <th>목</th>
        <th>금</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th>1교시</th>
        <td>국어</td>
        <!-- 수학이 1~2교시 연속 → rowspan으로 세로 2칸 병합 -->
        <td rowspan="2">수학</td>
        <td>영어</td>
        <td>국어</td>
        <td>수학</td>
      </tr>
      <tr>
        <th>2교시</th>
        <td>영어</td>
        <!-- 화요일 수학이 rowspan으로 이미 차지했으므로 td 하나 생략 -->
        <td>국어</td>
        <td>영어</td>
        <td>체육</td>
      </tr>
      <tr>
        <!-- 점심시간: 가로 전체 5칸 병합 -->
        <th>점심</th>
        <td colspan="5">점심시간 (12:00 ~ 13:00)</td>
      </tr>
    </tbody>
  </table>
</body>
</html>

줄별 코드 설명

줄 코드 설명
31 <td rowspan="2">수학</td> 이 셀이 세로 방향으로 2행에 걸쳐 확장됩니다. 아래 행에서 해당 위치의 <td>를 하나 생략해야 합니다
43 <td colspan="5">점심시간 ...</td> 이 셀이 가로 방향으로 5칸(월~금)을 차지합니다

주의: rowspan이나 colspan을 사용할 때는 병합된 칸 수만큼 다른 <td>를 빼야 표가 올바르게 그려집니다. 한 칸이 남거나 부족하면 표 구조가 어긋납니다.

비교 테이블¶

구분 <th> <td>
역할 헤더 셀 (제목) 데이터 셀
기본 스타일 굵은 글씨, 가운데 정렬 일반 글씨, 왼쪽 정렬
접근성 scope 속성으로 범위 지정 가능 없음
사용 위치 <thead>, 행/열 첫 칸 <tbody>, <tfoot>

절 요약¶

  • <table> → <thead>/<tbody> → <tr> → <th>/<td> 계층 구조로 표를 만듭니다
  • <th>는 헤더 셀, <td>는 데이터 셀로 의미가 다릅니다
  • colspan은 가로 병합, rowspan은 세로 병합입니다
  • 표는 데이터 정리에만 사용하고, 레이아웃 목적으로 사용하지 않습니다

3.4 입력 폼 만들기¶

도입¶

웹에서 사용자의 정보를 받으려면 폼(Form)이 필요합니다. 회원가입, 로그인, 검색창, 설문조사 — 이 모두가 폼을 활용합니다. 폼은 종이 신청서의 빈칸과 체크 항목, 제출 버튼을 웹에 구현한 것과 같습니다. 이 절에서는 다양한 입력 요소와 함께, 레이블을 연결하여 접근성을 높이는 방법을 익힙니다.

핵심 개념 설명¶

폼(form) 태그와 입력 요소¶

<form> 태그는 입력 요소들을 하나의 묶음으로 감쌉니다. 사용자가 "제출" 버튼을 누르면 폼 안의 데이터가 서버로 전송됩니다.

<form action="" method="">

항목 내용
설명 사용자 입력 요소를 묶어 데이터를 전송하는 컨테이너
주요 속성 action: 데이터를 전송할 서버 URL (생략 시 현재 URL)
method: 전송 방식. get(URL에 데이터 노출) 또는 post(데이터 숨김)
사용 예 <form action="/submit" method="post">

다양한 input 타입¶

<input> 태그는 type 속성에 따라 완전히 다른 입력 컨트롤이 됩니다.

type 표시 용도
text 한 줄 텍스트 박스 이름, 주소 등 일반 텍스트
email 한 줄 텍스트 박스 이메일 주소 (형식 자동 검증)
password 입력 내용이 ●●●로 가려짐 비밀번호
number 숫자 입력창 (위아래 화살표) 나이, 수량
tel 한 줄 텍스트 박스 전화번호 (모바일에서 숫자 키패드)
checkbox 체크 박스 (다중 선택) 여러 항목 중 복수 선택
radio 라디오 버튼 (단일 선택) 여러 항목 중 하나만 선택

file 파일 선택 버튼 파일 업로드

reset 초기화 버튼 폼 내용 모두 지우기

label과 input 연결로 접근성 높이기¶

레이블(label)은 입력 요소가 어떤 정보를 입력받는지 설명하는 역할을 합니다. 단순히 보기 좋으라고 두는 텍스트가 아닙니다. <label>과 <input>을 명시적으로 연결하면 두 가지 큰 이점이 생깁니다.

  1. 접근성: 스크린 리더가 입력 필드에 포커스할 때 레이블 텍스트를 함께 읽어 사용자가 무엇을 입력해야 하는지 알 수 있습니다
  2. 클릭 편의성: 레이블 텍스트를 클릭해도 연결된 입력 필드에 포커스가 이동합니다

연결 방법은 두 가지입니다.

<!-- 방법 1: for-id 연결 (권장) -->
<label for="username">사용자 이름</label>
<input type="text" id="username" name="username">

<!-- 방법 2: label로 input 감싸기 -->
<label>
  사용자 이름
  <input type="text" name="username">
</label>

줄별 코드 설명

줄 코드 설명
2 <label for="username"> for 속성 값이 연결할 input의 id와 일치해야 합니다
3 <input id="username"> id="username"으로 label과 연결됩니다. name은 서버로 전송 시 사용되는 키 값입니다

주의: label과 input을 연결할 때 for와 id는 반드시 완전히 일치해야 합니다. 대소문자도 구분됩니다. for="UserName"과 id="username"은 연결되지 않습니다.

다음 코드는 다양한 입력 타입과 레이블이 연결된 회원가입 폼을 보여줍니다.

  • <input type="..."> 의 type 속성에 따라 텍스트·이메일·비밀번호·체크박스·라디오 등 다양한 입력 컨트롤이 됩니다
  • <label for="아이디">와 <input id="아이디">를 짝지어 연결하면 접근성과 사용성이 높아집니다
  • <select>는 드롭다운 목록, <textarea>는 여러 줄 텍스트 입력에 사용합니다

3.5 폼 유효성 검사 기초¶

도입¶

폼에 데이터를 입력할 때 빈칸을 비워두거나, 이메일 형식이 아닌 텍스트를 넣거나, 너무 짧은 비밀번호를 입력하는 상황이 발생합니다. 폼 유효성 검사(Form Validation)는 이런 잘못된 입력을 제출 전에 미리 걸러냅니다. HTML5부터는 JavaScript 없이 브라우저가 기본적으로 검증해 주는 기능이 내장되어 있습니다.

핵심 개념 설명¶

required — 필수 입력 지정하기¶

required 속성이 붙은 필드가 비어 있으면 폼을 제출할 수 없습니다. 브라우저가 자동으로 경고 메시지를 표시합니다.

<label for="name">이름 *</label>
<input type="text" id="name" name="name" required>

required는 값이 없는 불리언 속성이므로 required="required"처럼 쓰지 않아도 됩니다.

type별 자동 검증¶

입력 필드의 type 속성만으로도 자동 검증이 이루어집니다.

type 자동 검증 내용
email @가 포함된 이메일 형식 여부 확인
url https:// 등 URL 형식 여부 확인
number 숫자만 입력 가능, min·max 범위 검증
tel 형식 자동 검증은 없음. 모바일에서 숫자 키패드 표시

min, max, minlength, maxlength, pattern — 입력 제약 두기¶

입력 제약 속성 모음

속성 적용 대상 설명
required 모든 입력 필수 입력 (비워두면 제출 불가)
min number, date, range 최솟값
max number, date, range 최댓값
minlength text, email, password 등 최소 글자 수
maxlength text, email, password 등 최대 글자 수
pattern text, email, password 등 정규식 패턴 일치 여부 검사
step number, range, date 등 입력 간격 (예: 5씩 증가)

코드로 확인하기 — 유효성 검사가 적용된 회원가입 폼¶

다음 코드는 다양한 유효성 검사 속성이 적용된 완전한 폼을 보여줍니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>폼 유효성 검사 예제</title>
  <style>
    body { font-family: sans-serif; max-width: 480px; margin: 40px auto; padding: 0 20px; }
    .form-group { margin-bottom: 16px; }
    label { display: block; margin-bottom: 4px; font-weight: bold; }
    input, textarea { width: 100%; padding: 8px; border: 1px solid #ccc;
      border-radius: 4px; box-sizing: border-box; }
    /* 브라우저가 유효성 검사를 통과한 필드에 초록 테두리 표시 */
    input:valid { border-color: #4caf50; }
    /* 사용자가 입력을 시작했지만 형식이 맞지 않으면 빨간 테두리 */
    input:invalid:not(:placeholder-shown) { border-color: #e53935; }
    .hint { font-size: 12px; color: #777; margin-top: 4px; }
    button { padding: 10px 24px; background: #4a90e2; color: white;
      border: none; border-radius: 4px; cursor: pointer; }
  </style>
</head>
<body>
  <h1>이벤트 신청 폼</h1>

  <form action="/apply" method="post" novalidate>

    <!-- 필수 + 이름 2글자 이상 -->
    <div class="form-group">
      <label for="name">이름 <span aria-label="필수">*</span></label>
      <input
        type="text"
        id="name"
        name="name"
        required
        minlength="2"
        maxlength="20"
        placeholder="두 글자 이상 입력"
      >
      <p class="hint">2~20자 이내로 입력하세요.</p>
    </div>

    <!-- 이메일 형식 자동 검증 + 필수 -->
    <div class="form-group">
      <label for="email">이메일 <span aria-label="필수">*</span></label>
      <input
        type="email"
        id="email"
        name="email"
        required
        placeholder="example@email.com"
      >
    </div>

    <!-- 나이: 숫자, 최솟값/최댓값 제한 -->
    <div class="form-group">
      <label for="age">나이 <span aria-label="필수">*</span></label>
      <input
        type="number"
        id="age"
        name="age"
        required
        min="14"
        max="100"
        placeholder="14 이상 100 이하"
      >
      <p class="hint">14세 이상 100세 이하만 신청 가능합니다.</p>
    </div>

    <!-- 전화번호: 패턴 검증 (010-XXXX-XXXX 형식) -->
    <div class="form-group">
      <label for="phone">전화번호</label>
      <input
        type="tel"
        id="phone"
        name="phone"
        pattern="010-[0-9]{4}-[0-9]{4}"
        placeholder="010-1234-5678"
        title="010-XXXX-XXXX 형식으로 입력하세요"
      >
      <p class="hint">010-XXXX-XXXX 형식으로 입력하세요.</p>
    </div>

    <!-- 라디오 버튼: 필수 선택 -->
    <div class="form-group">
      <p><strong>참가 방식 <span aria-label="필수">*</span></strong></p>
      <input type="radio" id="online" name="join-type" value="online" required>
      <label for="online">온라인</label>

      <input type="radio" id="offline" name="join-type" value="offline">
      <label for="offline">오프라인</label>
    </div>

    <!-- 약관 동의: 체크박스 필수 -->
    <div class="form-group">
      <input type="checkbox" id="agree" name="agree" required>
      <label for="agree">
        <a href="/terms" target="_blank">이용약관</a>에 동의합니다 (필수)
      </label>
    </div>

    <button type="submit">신청하기</button>
  </form>
</body>
</html>

"신청하기" 버튼을 클릭하면 유효성 검사가 실행됩니다. 비어 있거나 형식이 맞지 않는 필드가 있으면 브라우저가 자동으로 해당 필드로 스크롤하고 오류 메시지를 표시합니다.

줄별 코드 설명

줄 코드 설명
23 novalidate 이 속성을 추가하면 브라우저 기본 검증을 끕니다. JavaScript로 직접 검증을 구현할 때 사용합니다. 여기서는 CSS :valid/:invalid 스타일 데모를 위해 잠시 제거해야 합니다
27 <span aria-label="필수">*</span> 별표(*)가 시각적 필수 표시임을 스크린 리더에게도 알립니다
31 required 빈 값으로 제출 시 브라우저가 "이 필드를 입력하세요" 메시지를 표시합니다
32 minlength="2" 최소 2글자 이상 입력해야 합니다. 더 짧으면 제출이 막힙니다
33 maxlength="20" 최대 20글자까지만 입력됩니다. 초과 입력 자체를 막습니다
56 min="14" max="100" 14 미만이나 100 초과를 입력하면 "이 값은 14 이상이어야 합니다" 등의 메시지가 표시됩니다
66 pattern="010-[0-9]{4}-[0-9]{4}" 정규식 패턴. 010- 뒤에 숫자 4자리, -, 숫자 4자리 형식만 허용합니다
67 title="010-XXXX-XXXX 형식..." 패턴 오류 시 브라우저가 표시하는 추가 안내 메시지입니다
13 input:valid CSS에서 유효성 검사를 통과한 필드에 스타일을 적용합니다
15 input:invalid:not(:placeholder-shown) 입력을 시작했지만 아직 형식이 맞지 않는 경우에만 오류 스타일을 적용합니다. :placeholder-shown은 placeholder가 보이는(아무것도 입력 안 된) 상태를 의미합니다

베스트 프랙티스: 브라우저 기본 유효성 검사는 편리하지만, 실제 서비스에서는 서버 측 검증도 반드시 함께 수행해야 합니다. 클라이언트 측 검증은 사용자 편의를 위한 것이고, 서버 검증은 보안을 위한 것입니다. 둘 중 하나만 해서는 안 됩니다.

팁: title 속성을 pattern과 함께 쓰면 패턴이 맞지 않을 때 브라우저가 안내 메시지를 표시합니다. 사용자가 올바른 형식을 금방 파악할 수 있게 구체적으로 적어 주세요.

절 요약¶

  • required는 필수 입력 필드 지정, 비어 있으면 제출이 막힙니다
  • type="email", type="number" 등은 형식 자동 검증이 내장되어 있습니다
  • min/max는 숫자나 날짜 범위, minlength/maxlength는 텍스트 길이를 제한합니다
  • pattern에 정규식을 써서 더 세밀한 형식 검증을 합니다
  • 브라우저 검증만으로는 충분하지 않으며, 서버 측 검증도 반드시 수행해야 합니다

FAQ¶

Q1: 이미지 경로가 맞는데 왜 이미지가 안 보이나요?

A1: 경로가 대소문자를 구분하는지 확인하세요. 윈도우에서는 Images/photo.jpg와 images/photo.jpg가 같지만, 리눅스 서버(대부분의 웹 서버)는 대소문자를 구분합니다. 서버에 올렸을 때 깨지는 이미지의 대부분은 이 문제입니다. 파일명과 폴더명을 항상 소문자로 통일하는 습관을 들이세요.

Q2: 폼에서 name 속성과 id 속성의 차이는 무엇인가요?

A2: id는 HTML 문서 내에서 요소를 고유하게 식별하는 값으로, CSS 선택자(#아이디)나 label for 연결, JavaScript getElementById에 사용됩니다. name은 폼 데이터가 서버로 전송될 때 데이터의 키(key) 이름이 됩니다. 예를 들어 name="email"이면 서버에 email=user@example.com 형태로 데이터가 전달됩니다. 둘 다 같은 값으로 쓰는 것이 일반적입니다.

Q3: <table>을 레이아웃으로 쓰면 안 되는 이유가 무엇인가요?

A3: 과거에는 CSS 레이아웃 도구가 부족해 표를 레이아웃에 썼지만, 현재는 잘못된 관행입니다. 첫째, 스크린 리더가 표를 "데이터 표"로 읽어 시각 장애 사용자에게 혼란을 줍니다. 둘째, 반응형 디자인 구현이 어렵습니다. 셋째, 코드 구조가 복잡해져 유지보수가 힘들어집니다. 레이아웃은 CSS Flexbox와 Grid(5~6장에서 배울 내용)로 구현하세요.

Q4: target="_blank" 없이도 새 탭에서 열리게 할 수 있나요?

A4: 직접적으로는 어렵습니다. target="_blank"가 표준 방법입니다. 다만 사용자가 링크를 Ctrl + 클릭(윈도우) 또는 Cmd + 클릭(맥)하면 target 속성에 관계없이 새 탭으로 열립니다. 사용성 관점에서 같은 사이트 내 링크는 target="_blank" 없이 현재 탭에서 열고, 외부 사이트 링크만 새 탭으로 여는 것이 일반적인 관례입니다.

Q5: required 속성만으로 실제 서비스 폼 검증이 충분한가요?

A5: 충분하지 않습니다. required 등 브라우저 검증은 개발자 도구에서 해당 속성을 제거하거나, novalidate를 추가하거나, HTTP 요청을 직접 조작하면 우회할 수 있습니다. 반드시 서버 측에서도 동일한 검증을 수행해야 합니다. 클라이언트 측 검증은 사용자 편의(빠른 피드백)를 위한 것이고, 보안은 서버 측 검증이 담당합니다.

장 요약¶

이번 장에서는 HTML을 더욱 풍부하게 만드는 네 가지 핵심 요소를 배웠습니다. 하이퍼링크로 페이지 간 연결을 만들고, 절대 경로와 상대 경로를 구분하여 정확한 경로를 작성하는 방법을 익혔습니다. 이미지와 멀티미디어를 삽입할 때는 alt 속성이 접근성과 SEO 모두에 중요하다는 점을 확인했습니다. 표(Table)는 데이터를 시각적으로 정리하는 도구로, thead·tbody로 의미를 구분하고 colspan·rowspan으로 셀을 병합할 수 있습니다. 마지막으로 <form>과 다양한 <input> 타입으로 사용자 입력을 받고, label을 연결하여 접근성을 높이며, required·pattern·min·max 등의 속성으로 브라우저 기본 유효성 검사를 적용하는 방법까지 배웠습니다.
