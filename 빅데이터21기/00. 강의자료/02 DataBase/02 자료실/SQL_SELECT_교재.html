각 예제는 문법 구조 분해 → 실무 의미 → 동작 원리·흔한 실수 → 응용 순으로 깊이 있게 설명하고, 실제 실행 결과와 행수를 그대로 보여 준다. 상단 버튼으로 난이도별 필터, 각 코드의 복사 버튼으로 바로 실행할 수 있다.

데이터셋 / ERD

정규화된 5개 테이블. 화살표는 외래키 참조 방향(자식 → 부모).

categories ◀---- products ◀---- order_items ----► orders ----► customers (상품분류) (상품) (주문상세 1:N) (주문헤더) (회원) 14행 1,000행 999,995행 200,000행 50,000행 핵심 관계 - products.category_id → categories.category_id - orders.customer_id → customers.customer_id - order_items.order_id → orders.order_id (한 주문에 여러 품목 = 1:N) - order_items.product_id → products.product_id

SELECT 논리적 실행 순서

SQL은 적힌 순서가 아니라 논리적 순서로 평가된다. 이걸 알면 별칭/필터/집계 규칙이 한 번에 이해된다.

FROM / JOIN→ WHERE→ GROUP BY→ HAVING→ SELECT (표현식·별칭)→ DISTINCT→ ORDER BY→ LIMIT / OFFSET

함의: WHERE에선 SELECT 별칭을 못 쓴다(아직 평가 전). 반면 ORDER BY·GROUP BY는 별칭 사용 가능. 집계 결과로 거르는 건 WHERE가 아니라 HAVING. 윈도우 함수는 SELECT 단계에서 계산되므로 WHERE로 직접 못 거르고 서브쿼리로 감싸야 한다.

⚠️ 합성 데이터 특성 — 분석 전 반드시 알아 둘 것

이 데이터는 난수 없이 일련번호 공식으로 생성되어(누가 돌려도 동일) 학습에 이상적이지만, 실제 세계엔 없는 인위적 규칙이 있다. 모르고 교차분석하면 잘못된 인사이트를 얻는다.

  • 모든 회원이 주문을 가진다 · 모든 상품이 한 번 이상 팔린다 — '미주문 회원/미판매 상품' 안티조인 결과는 0(예제 18·27은 이를 우회).
  • 등급(grade)과 주문상태(status)가 인위적으로 상관된다. 등급×상태 교차표는 현실 의미가 없으니 피한다.
  • 한 회원의 주문 4건은 상태가 모두 동일(생성식 mod 100 주기). 회원별 상태 다양성 분석은 무의미.
  • 반면 가격·재고·날짜·분류 분포는 고르게 퍼져 정렬·구간·범위·집계 실습엔 적합.

연습문제 10선

난이도 순. 먼저 직접 작성한 뒤 정답을 펼쳐 비교하자. 모든 정답값은 실제 실행으로 검증했다.

부록 · SELECT 성능과 인덱스

문법을 익혔다면, 대용량(order_items 100만 행)에서 왜 느린지/빠른지를 보는 눈이 다음 단계다.

TIP 1

실행계획부터 본다 — EXPLAIN ANALYZE

EXPLAIN ANALYZE
SELECT * FROM order_items WHERE product_id = 500;
읽는 법 외래키 컬럼은 PostgreSQL이 자동 인덱스를 만들지 않는다. 인덱스가 없으면 100만 행을 전부 훑는 Seq Scan. 출력의 actual time이 실제 소요 시간.
TIP 2

인덱스 생성 후 재측정

CREATE INDEX idx_order_items_product_id ON order_items (product_id);

EXPLAIN ANALYZE
SELECT * FROM order_items WHERE product_id = 500;   -- 이제 Index Scan
효과 같은 쿼리가 Seq Scan → Index Scan으로 바뀌며 시간이 급감. 조회 빈도 높은 외래키/필터 컬럼이 인덱스 1순위.
TIP 3

범위 조회 인덱스 · 페이징 주의

CREATE INDEX idx_orders_order_date ON orders (order_date);

EXPLAIN ANALYZE
SELECT count(*) FROM orders
WHERE order_date >= DATE '2024-01-01' AND order_date < DATE '2024-02-01';
메모 날짜 범위 조회가 잦으면 order_date 인덱스가 효자. 큰 OFFSET 페이징(예제 5)은 앞 행을 버리며 훑어 느리다 → 키셋 페이지네이션(WHERE id > 마지막id)으로 대체.
