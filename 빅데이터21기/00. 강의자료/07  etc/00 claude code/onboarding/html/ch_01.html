첫날: Claude Code 설치·인증과 첫 세션

이 장의 학습 목표

  • 주어진 Windows 11 작업 머신에서 네이티브 설치 관리자 또는 npm으로 Claude Code를 설치하고, claude --version과 Git Bash 실행으로 설치 완료를 확인할 수 있습니다.
  • 구독(Pro/Max)과 API 키 두 인증 방식의 과금 차이를 한 가지 이상 들어 구분하고, 의도한 방식으로 로그인한 뒤 /status로 그 방식이 맞는지 확인할 수 있습니다.
  • 주어진 실습 폴더에서 대화형 REPL(claude)을 열어 첫 작업을 지시해 도구 호출 1사이클을 완료하고, 1회성(-p) 실행과 언제 무엇을 쓰는지 구분해 설명할 수 있습니다.
  • 진행 중 세션을 중단(Esc)·재개(--continue/--resume)해 직전 맥락이 이어지는지 확인하고, /status로 인증·세션 상태를 점검할 수 있습니다.

이 책은 기존 팀의 FastAPI 저장소에 작은 기능 하나를 추가해 첫 PR(Pull Request, 풀 리퀘스트)까지 올리는 신입 개발자의 여정을 따라갑니다. 그 여정의 출발점은 단 하나입니다. 옆자리에 앉아 함께 코드를 읽고 고치고 실행해 줄 페어 프로그래머를 내 자리에 들이는 것, 곧 Claude Code를 설치하고 인증해 첫 세션을 여는 것입니다.

이 장의 선수 지식: 이 장은 책의 첫 단원(u1)이며, 앞서 배운 이 책의 개념을 전제하지 않습니다. 다만 책 전체의 선수 지식(Python 기초·터미널·git·HTTP 기초 — 자세한 내용은 머리말 「이 책에 대하여」 참고)은 가정합니다. 설치·인증·첫 세션 자체는 Claude Code가 처음이어도 따라올 수 있도록 모든 동작을 단계로 풀어 설명합니다.

이 장에서 가르치는 개념은 하나입니다.

  • 개념 c01 — 설치·인증과 첫 세션(installation, authentication, and first session): Windows 11에 Claude Code를 설치하고, 내 의도에 맞는 방식으로 인증하고, 대화형 REPL과 1회성 실행을 구분해 첫 작업을 지시하고, 세션을 중단·재개하는 법.

1. 도입: 팀에 합류한 첫날, 페어 프로그래머를 들이다

입사 첫날의 풍경은 대개 비슷합니다. 노트북을 받고, 사번으로 로그인하고, 팀의 코드 저장소 주소를 전달받습니다. 그리고 곧바로 막막함이 찾아옵니다. 수백 개의 파일, 한 번도 본 적 없는 폴더 구조, "이게 어디서 호출되는 거지?"라는 질문이 끝없이 이어집니다. 신입에게 가장 비싼 자원은 시간이 아니라 물어볼 수 있는 사람입니다. 시니어 개발자는 바쁘고, 같은 질문을 두 번 묻기는 눈치가 보입니다.

Claude Code는 바로 이 자리를 메우는 도구입니다. 지치지 않고, 같은 질문을 백 번 물어도 괜찮으며, 저장소 전체를 몇 초 만에 훑어 "이 API는 무엇을 하고 엔드포인트가 무엇인지" 설명해 주는 페어 프로그래머입니다. 단순히 설명만 하는 것이 아니라, 파일을 직접 열어 읽고, 코드를 고치고, 테스트를 돌려 결과를 보여 줍니다.

그런데 이 페어 프로그래머를 제대로 쓰려면 첫날에 세 가지를 정확히 해 두어야 합니다. 설치(내 컴퓨터에 도구를 올리기), 인증(내 계정·요금제로 연결하기), 그리고 첫 세션(대화를 시작해 도구가 일하는 방식을 직접 보기)입니다. 이 세 가지를 대충 넘기면, 뒤에서 "왜 과금이 되지?", "왜 명령이 안 먹히지?", "어제 하던 작업이 사라졌네?" 같은 문제로 되돌아오게 됩니다. 이 장은 그 세 가지를 한 번에, 정확히 끝내는 것을 목표로 합니다.

한눈에 보는 이 장의 지도

  • 페어 프로그래머를 자리에 앉히기 → 설치(PowerShell 네이티브 설치 관리자 또는 npm)
  • 도구가 Bash 명령을 쓸 수 있게 하기 → Git for Windows(Git Bash) 준비
  • 내 요금제로 연결하기 → 인증(구독 Pro/Max 브라우저 로그인 vs API 키)
  • 대화를 시작하기 → 대화형 REPL(claude)
  • 한 번만 묻고 답만 받기 → 1회성 실행(claude -p)
  • 자리를 비웠다 돌아오기 → 세션 재개(--continue·--resume)

2. 정의: Claude Code란 무엇인가(터미널·IDE·웹)

정의

이 장의 핵심 개념을 한 문장으로 정의하겠습니다.

Claude Code(클로드 코드) 는 터미널·IDE·웹에서 동작하는 Anthropic 공식 에이전트형 코딩 CLI(agentic coding CLI) 로, 단순히 다음 코드를 제안하는 자동완성이 아니라 파일을 직접 읽고 편집하고 명령을 실행하며 커밋까지 돕는 AI 페어 프로그래머입니다. 그리고 첫 세션(first session) 이란 설치·인증을 마친 뒤 대화형 REPL을 처음 열어, 자연어 지시에 에이전트가 도구를 호출해 변경을 만들어 내는 과정을 처음으로 관찰하는 출발점입니다.

용어를 하나씩 정리하겠습니다.

  • CLI(Command-Line Interface, 명령줄 인터페이스): 마우스 클릭이 아니라 터미널에 명령어를 입력해 쓰는 프로그램입니다. Claude Code의 기본 진입점은 터미널에 claude라고 입력하는 것입니다.
  • 에이전트(agent): 목표를 받아 스스로 도구를 골라 쓰며 여러 단계를 거쳐 작업을 완수하는 프로그램입니다. "다음 한 줄"을 제안하는 데서 그치지 않고, 읽고·계획하고·실행하고·확인하기를 반복합니다.
  • REPL(Read-Eval-Print Loop, 읽고-실행하고-출력하는 반복 루프): 입력을 받아 처리하고 결과를 보여 주기를 반복하는 대화형 화면입니다. claude를 실행하면 나타나는 대화 화면이 바로 REPL입니다.

같은 엔진, 여러 표면

Claude Code는 하나의 엔진을 여러 표면(surface) 에서 쓸 수 있게 제공합니다. 어디서 쓰든 "에이전트가 도구를 호출해 일한다"는 핵심은 같습니다.

표면 진입 방법 잘 맞는 상황
터미널(CLI) 셸에서 claude 실행 대부분의 개발 작업, 스크립트·CI 연동 (이 책의 기본 무대)
IDE 확장 VS Code·JetBrains 확장에서 호출 편집기 안에서 diff를 보며 작업할 때
웹 브라우저에서 클라우드 작업공간 실행 로컬 설치 없이 원격에서 작업할 때

이 책은 가장 이식성이 좋고 자동화에 직결되는 터미널(CLI) 을 기본 무대로 삼습니다. 터미널에서 익힌 개념은 IDE·웹에 그대로 옮겨집니다.

자동완성과의 한 줄 차이 자동완성 도구는 "지금 타이핑하는 커서 주변"만 보고 다음 몇 줄을 제안합니다. Claude Code는 "이 저장소에서 tasks 라우터를 찾아 새 엔드포인트를 추가하고 테스트까지 통과시켜 줘" 같은 완결된 작업을 받아 스스로 파일을 탐색·편집·실행합니다. 이 차이는 2장에서 에이전트 루프로 자세히 다룹니다.

3. Windows 11 설치: PowerShell 네이티브 설치 관리자와 npm

이제 페어 프로그래머를 자리에 앉혀 보겠습니다. 이 책의 대상 환경은 Windows 11입니다. 설치 방법은 두 갈래이며 둘 중 하나만 고르면 됩니다. 공식이 권장하는 방법은 네이티브 설치 관리자입니다.

방법 1: PowerShell 네이티브 설치 관리자(권장)

Windows 11의 PowerShell(시작 메뉴에서 "PowerShell" 검색)을 열고 다음 한 줄을 입력합니다.

powershell
irm https://claude.ai/install.ps1 | iex

이 명령은 두 부분으로 이루어져 있습니다. irm은 Invoke-RestMethod의 별칭으로 주어진 주소에서 설치 스크립트를 내려받고, iex는 Invoke-Expression의 별칭으로 그 스크립트를 실행합니다. 설치가 끝나면 바이너리가 사용자 폴더(C:\Users\사용자이름\.local\bin)에 놓이므로 관리자 권한이 필요 없습니다. 네이티브 설치본은 백그라운드에서 자동으로 최신 버전으로 갱신됩니다.

irm이 인식되지 않는다는 오류가 나면 'irm' 용어가 cmdlet... 이름으로 인식되지 않습니다라는 메시지가 보이면 지금 연 창이 PowerShell이 아니라 명령 프롬프트(CMD) 입니다. irm은 PowerShell 전용 별칭이므로, 시작 메뉴에서 정확히 "PowerShell"을 다시 검색해 실행한 뒤 명령을 입력합니다.

방법 2: npm 전역 설치(대안)

이미 Node.js가 설치돼 있다면 npm으로 설치할 수도 있습니다. PowerShell이나 Git Bash에서 다음을 입력합니다.

bash
npm install -g @anthropic-ai/claude-code

-g는 전역(global) 설치라는 뜻으로, 어느 폴더에서나 claude 명령을 쓸 수 있게 합니다. 패키지 이름은 정확히 @anthropic-ai/claude-code입니다.

설치 확인

어느 방법을 썼든 새 터미널 창을 열고 버전을 확인합니다. (설치 직후에는 PATH가 갱신되도록 터미널을 새로 여는 것이 안전합니다.)

bash
claude --version
console
2.0.x (Claude Code)

버전 번호가 출력되면 설치는 성공입니다. 숫자는 시점에 따라 다릅니다.

4. Git for Windows(Bash 도구)와 작업 디렉터리 준비

Claude Code는 명령을 실행할 때 셸(shell) 을 빌려 씁니다. Windows에는 기본으로 PowerShell과 CMD가 있지만, Claude Code의 Bash 도구는 이름 그대로 Bash 셸을 기대합니다. 그래서 Windows에서는 Git for Windows(Git Bash 포함)를 함께 설치하는 것을 권장합니다. Git for Windows가 있으면 Claude Code가 그 Bash를 도구로 사용하고, 없으면 일부 Bash 기반 명령이 어색하게 동작할 수 있습니다. 또한 9장에서 다룰 git 커밋·PR 워크플로에도 Git이 반드시 필요합니다.

git-scm.com에서 Git for Windows 설치 관리자를 내려받아 설치한 뒤, 설치를 확인합니다.

bash
git --version
console
git version 2.45.0.windows.1

작업 디렉터리 준비

Claude Code는 "지금 터미널이 위치한 폴더"를 작업 대상으로 삼습니다. 그래서 도구를 열기 전에 작업할 폴더로 먼저 이동하는 습관이 중요합니다. 연습용 빈 폴더를 하나 만들어 보겠습니다.

bash
mkdir onboarding-practice
cd onboarding-practice

mkdir은 폴더를 만들고, cd는 그 폴더로 이동합니다. 이제 이 폴더 안에서 claude를 실행하면, Claude Code는 이 폴더를 작업 무대로 인식합니다.

작업 폴더를 먼저 정하는 이유 Claude Code는 실행한 위치의 폴더와 그 하위만 기본 작업 범위로 봅니다. 엉뚱한 상위 폴더(예: C:\Users\사용자)에서 도구를 열면 수많은 파일을 작업 대상으로 오해할 수 있습니다. "작업할 폴더로 cd 한 뒤 claude"를 첫날부터 몸에 익히면 사고를 줄입니다.

5. 동작 원리: 인증 흐름(구독 vs API 키)

설치를 마쳤다면, 이제 Claude Code를 내 계정·요금제에 연결해야 합니다. 이 단계에서 신입이 가장 자주 혼동하는 지점이 바로 인증 방식입니다. 인증에는 두 갈래가 있고, 둘은 요금이 청구되는 방식이 다릅니다.

두 가지 인증 방식

방식 누가 쓰나 어떻게 청구되나
구독(Pro/Max) Claude 구독 요금제를 쓰는 개인·팀원 월 구독료 안에서 사용량 소진
API 키(ANTHROPIC_API_KEY) Anthropic 플랫폼 API 사용자 토큰 사용량만큼 종량 과금

구독 방식은 Claude Pro 또는 Max 요금제를 결제한 사람이 쓰는 방법입니다. claude를 처음 실행하면 브라우저가 열리고, Claude 계정으로 로그인하면 구독 사용량으로 Claude Code가 동작합니다. 신입 온보딩에서는 대개 이 방식을 씁니다.

API 키 방식은 환경 변수 ANTHROPIC_API_KEY에 발급받은 키를 넣어 두는 방법입니다. 이 경우 Anthropic 플랫폼에서 토큰 사용량만큼 종량 과금이 발생합니다.

핵심: 두 방식은 같은 자리를 두고 경쟁한다

여기서 가장 중요한 동작 원리는 이것입니다. ANTHROPIC_API_KEY 환경 변수가 설정돼 있으면, Claude Code는 구독 대신 그 API 키를 우선해 사용합니다. 즉 구독 요금제를 쓰려고 했는데 예전에 실습하느라 설정해 둔 API 키가 환경 변수에 남아 있으면, 본인도 모르게 종량 과금이 발생할 수 있습니다.

따라서 인증 흐름은 다음 분기로 정리됩니다.

  1. claude를 실행한다.
  2. Claude Code가 ANTHROPIC_API_KEY 환경 변수를 확인한다.
  3. 변수가 있으면 → 그 API 키로 동작(종량 과금).
  4. 변수가 없으면 → 브라우저 로그인으로 구독(Pro/Max) 사용량을 쓴다.
  5. 어느 쪽으로 인증됐는지 /status로 확인한다.

그래서 구독을 쓰려면 ANTHROPIC_API_KEY를 설정하지 않아야 합니다. 이미 설정돼 있다면 비워 두어야 구독 로그인으로 넘어갑니다.

Windows에서 환경 변수 확인·제거 PowerShell에서 현재 세션의 API 키가 설정돼 있는지 확인하려면 다음을 입력합니다.

powershell
echo $env:ANTHROPIC_API_KEY

아무것도 출력되지 않으면 설정돼 있지 않은 것입니다. 값이 보인다면(그리고 구독을 쓰고 싶다면) 현재 PowerShell 세션에서 임시로 비울 수 있습니다.

powershell
Remove-Item Env:\ANTHROPIC_API_KEY

영구적으로 설정해 둔 경우라면 Windows의 "시스템 환경 변수 편집"에서 사용자 변수 목록의 ANTHROPIC_API_KEY를 제거해야 합니다.

6. worked example: 설치 → 로그인 → /status로 인증 확인

지금까지 배운 설치·인증을 처음부터 끝까지 한 번 따라가 보겠습니다. 이것은 첫날 누구나 한 번은 거치는 정확한 절차입니다.

1단계: 설치하고 버전 확인

PowerShell에서 설치하고 새 터미널에서 버전을 확인합니다.

powershell
irm https://claude.ai/install.ps1 | iex
console
Claude Code installed to C:\Users\jihoon\.local\bin

새 터미널을 열어 확인합니다.

bash
claude --version

2.0.x (Claude Code)

2단계: 작업 폴더로 이동해 첫 실행

bash

처음 claude를 실행하면 테마 선택 등 초기 설정을 묻고, 인증이 안 된 상태라면 브라우저가 열립니다. 브라우저에서 Claude 계정으로 로그인하고 권한을 승인하면 터미널로 돌아와 다음과 같은 대화형 REPL 화면이 나타납니다.

console
╭──────────────────────────────────────────────╮
│ ✻ Welcome to Claude Code                      │
│   /help 로 도움말, /status 로 상태 확인        │

>

> 프롬프트가 보이면 이제 자연어로 지시할 준비가 된 것입니다.

3단계: /status로 인증 방식 확인

REPL 안에서 슬래시 명령 /status를 입력합니다. 슬래시 명령은 자연어 지시가 아니라 Claude Code에 직접 내리는 제어 명령입니다.

console
> /status
console
Account: jihoon@team.com
Login method: Claude Max subscription
Model: claude-opus-4-x
Working directory: C:\Users\jihoon\onboarding-practice

여기서 Login method가 핵심입니다. Claude Max subscription(또는 Pro)이라고 나오면 구독으로 인증된 것이고, API key라고 나오면 종량 과금 방식으로 연결된 것입니다. 의도와 다르면 5장에서 본 대로 ANTHROPIC_API_KEY를 확인·제거하고 다시 로그인합니다.

이 절차에서 짚을 것

  • 설치 → 버전 확인: 버전 번호가 나와야 PATH에 정상 등록된 것입니다.
  • cd 후 claude: 작업 폴더 안에서 실행해야 그 폴더가 작업 무대가 됩니다.
  • 브라우저 로그인: ANTHROPIC_API_KEY가 없을 때만 구독 로그인으로 넘어갑니다.
  • /status: "내가 의도한 방식으로 인증됐는가"를 눈으로 확인하는 마지막 관문입니다. 첫날 이것을 확인하지 않으면 과금 방식을 모른 채 쓰게 됩니다.

7. 대화형 REPL과 1회성 실행(-p) 구분

Claude Code를 쓰는 방식은 크게 두 가지입니다. 둘의 차이를 처음부터 분명히 해 두면, 상황에 맞는 방식을 골라 쓸 수 있습니다.

대화형 REPL: claude

claude만 입력하면 앞에서 본 대화 화면(REPL)이 열립니다. 여기서는 사람과 대화하듯 여러 차례 지시를 주고받습니다. 에이전트가 파일을 고치면 검토하고, 추가 지시를 주고, 테스트를 돌리게 하고, 다시 고치게 합니다. 맥락이 누적되는 작업, 즉 한 번의 대화로 끝나지 않는 대부분의 개발 작업에 적합합니다.

1회성 실행(print 모드): claude -p "..."

질문 하나에 답 하나만 받고 끝내고 싶을 때는 -p(print) 플래그를 씁니다. REPL을 열지 않고, 명령 한 줄에 결과를 출력하고 곧바로 종료합니다.

bash
claude -p "이 폴더에 뭐가 있는지 한 줄로 요약해 줘"
console
이 폴더에는 아직 파일이 없는 빈 작업 디렉터리입니다.

-p 모드는 대화를 이어가지 않고 한 번 답하고 끝나므로, 셸 스크립트나 자동화 파이프라인에 끼워 넣기 좋습니다. "지금 빠르게 한 가지만 묻고 싶다"면 -p, "함께 작업을 진행하겠다"면 REPL입니다.

구분 대화형 REPL (claude) 1회성 실행 (claude -p "...")
화면 대화 화면이 열림 답만 출력하고 종료
맥락 여러 턴에 걸쳐 누적 한 번의 응답으로 끝
적합한 상황 함께 코드를 만들고 고치는 작업 빠른 질의, 스크립트·자동화
종료 /exit 또는 Ctrl+D 자동으로 종료

언제 무엇을 쓰나 지금 단계에서는 거의 항상 대화형 REPL을 씁니다. -p는 "폴더 요약 한 줄만 받기"처럼 한 번에 끝나는 단순 질의나, 나중에 자동화에 끼워 넣을 때 쓰는 도구라고 기억해 두면 됩니다.

8. worked example: 빈 폴더에서 첫 파일 생성·실행

이제 에이전트가 실제로 파일을 만들고 실행하는 모습을 직접 보겠습니다. 자동완성과의 차이를 눈으로 확인하는 순간입니다. 앞서 만든 onboarding-practice 빈 폴더에서 claude를 실행한 상태라고 가정합니다.

REPL에 다음과 같이 지시합니다.

console
> hello.py 파일을 만들어 "Hello, Claude Code!"를 출력하게 하고,
  python으로 실행해서 결과를 보여 줘.

에이전트는 먼저 hello.py를 만들겠다는 계획을 보여 주고, 파일을 생성한 뒤(부수효과가 있는 작업이므로 권한을 확인합니다 — 5장에서 상세히 다룹니다), 실행 명령을 돌립니다. 만들어진 파일은 다음과 같습니다.

python
print("Hello, Claude Code!")
# 출력: Hello, Claude Code!

그리고 에이전트가 python hello.py를 실행한 결과를 화면에 보여 줍니다.

console
> python hello.py
Hello, Claude Code!

여기서 자동완성과의 결정적 차이가 드러납니다. 자동완성이었다면 print(...) 한 줄을 제안하는 데서 끝나고, 파일 생성과 실행은 사람이 직접 해야 합니다. 에이전트는 파일을 만들고(쓰기), 명령을 실행하고(Bash), 결과를 확인하는 데까지 스스로 갑니다.

조금 더 실무에 가까운 예: 작은 함수

이 책의 실습 스택은 웹 백엔드(FastAPI)입니다. 본격적인 엔드포인트는 뒤에서 다루지만, 맛보기로 작은 인사 함수를 만들어 실행해 보겠습니다.

console
> greet.py를 만들어. 이름을 받아 "안녕하세요, {이름}님"을 돌려주는
  greet 함수와, greet("지훈")을 출력하는 코드를 넣고 실행해 줘.

에이전트가 만든 파일은 다음과 같습니다.

python
def greet(name: str) -> str:
    return f"안녕하세요, {name}님"


print(greet("지훈"))
# 출력: 안녕하세요, 지훈님

코드 줄별 해설

  • def greet(name: str) -> str: — 문자열 name을 받아 문자열을 돌려주는 함수를 정의합니다. : str, -> str은 타입 힌트로, 이 책의 코딩 컨벤션을 따릅니다.
  • return f"안녕하세요, {name}님" — f-string으로 받은 이름을 문장에 끼워 돌려줍니다.
  • print(greet("지훈")) — 함수를 호출한 결과를 화면에 출력합니다.
  • # 출력: 안녕하세요, 지훈님 — 실제 python greet.py 실행 결과와 정확히 일치합니다.

실행 결과를 직접 확인합니다.

console
> python greet.py
안녕하세요, 지훈님

이렇게 "지시 → 에이전트가 파일 생성 → 실행 → 결과 확인"까지가 한 흐름으로 이어지는 것이 에이전트형 코딩의 기본 모습입니다.

9. 세션 관리: 중단·재개(--continue/--resume)·종료

신입이 처음 당황하는 순간 중 하나가 "어제 하던 대화가 사라진 것 같다"입니다. Claude Code는 세션(대화)을 저장하므로, 닫았다가도 이어서 작업할 수 있습니다. 이 동작을 정확히 알아 두면 작업 맥락을 잃지 않습니다.

작업 중단: Esc

에이전트가 엉뚱한 방향으로 일하고 있을 때, Esc 키를 누르면 진행 중인 작업을 멈춥니다. 잘못된 지시를 줬다고 끝까지 기다릴 필요가 없습니다. 멈춘 뒤 지시를 다시 다듬어 주면 됩니다.

세션 종료: /exit 또는 Ctrl+D

대화를 끝내고 터미널로 나가려면 REPL에서 /exit를 입력하거나 Ctrl+D를 누릅니다.

console
> /exit

직전 세션 이어가기: --continue

터미널을 닫았다가 다시 같은 작업을 이어가고 싶으면, 작업 폴더에서 --continue(또는 짧게 -c)로 가장 최근 대화를 곧바로 복원합니다.

bash
claude --continue

이렇게 하면 직전 세션의 대화 내용과 맥락이 그대로 살아난 채 REPL이 열립니다. 에이전트는 어제 무엇을 하고 있었는지 기억합니다.

여러 세션 중 골라 재개: --resume

같은 폴더에서 여러 갈래의 작업을 했다면, --resume(또는 -r)으로 저장된 세션 목록을 보고 골라서 재개합니다.

bash
claude --resume
console
저장된 세션을 선택하세요:
  1. hello.py 만들고 실행 (3분 전)
  2. greet 함수 추가 (1시간 전)
  3. 폴더 구조 질문 (어제)

원하는 세션을 고르면 그 시점의 맥락으로 돌아갑니다.

명령 하는 일
Esc 진행 중인 작업 즉시 중단
/exit 또는 Ctrl+D 현재 세션 종료(터미널로 나감)
claude --continue (-c) 가장 최근 세션을 바로 이어감
claude --resume (-r) 저장된 세션 목록에서 골라 재개

--continue와 --resume의 차이 --continue는 "묻지 않고 가장 최근 것"을 바로 엽니다. 빠르게 어제 작업을 잇고 싶을 때 씁니다. --resume은 "어느 세션이었지?"를 고를 수 있게 목록을 보여 줍니다. 같은 폴더에서 여러 작업을 병행했을 때 유용합니다.

  2. M2 인증 확정: /status의 Login method가 의도한 방식(구독 또는 API 키)과 일치한다.
  3. M3 첫 산출물: 빈 폴더에서 greet.py(이름을 받아 인사말을 돌려주는 함수)를 에이전트로 만들고 실행해 출력을 확인한다.
  4. M4 세션 재개: 세션을 /exit로 닫은 뒤 claude --continue로 다시 열어 맥락이 이어지는지 확인한다.

산출물: 위 4단계의 명령과 결과를 적은 "첫 세션 기록" 메모(위 점검표 형식).

미니 프로젝트 자가체크

  • [ ] M1~M4를 모두 실제로 실행해 결과를 확인했다.
  • [ ] greet.py의 출력이 코드의 # 출력: 주석과 정확히 일치했다.
  • [ ] --continue로 연 세션이 직전 작업을 기억하고 있었다.
  • [ ] 인증 방식을 추측이 아니라 /status 출력으로 확정했다.

11. 이 책의 실습 저장소 준비 (이후 모든 장의 무대)

지금까지는 빈 폴더에서 hello.py 같은 작은 파일을 직접 만들어 보았습니다. 그러나 2장부터 다루는 일들 — 낯선 코드 파악(4장), 안전한 변경(5~6장), 테스트 검증(7장), CLAUDE.md 작성(8장), 첫 커밋·PR(9~10장), 그리고 종합 프로젝트(13~16장) — 은 모두 "팀에서 받은 기존 저장소" 하나를 무대로 합니다. 이 책은 그 저장소를 team-tasks-api 라는 작은 FastAPI 서비스로 함께 제공합니다. 신입이 첫 업무로 받는 "할 일(task) 관리 API"라고 생각하면 됩니다.

이 저장소는 책과 함께 제공되는 자료의 assets/team-tasks-api/ 폴더에 들어 있습니다. 지금 여러분의 작업 폴더로 복사해 두고, 이후 모든 장의 미니 프로젝트를 이 한 저장소에 누적해 나갑니다.

무엇이 들어 있나

team-tasks-api/
  main.py            # FastAPI 앱 진입점 + GET /health
  models.py          # 모델(Task, TaskCreate)과 status 열거형(todo, done)
  store.py           # 인메모리 저장소(create, get_all, get)
  routers/tasks.py   # GET /tasks 목록, POST /tasks 생성, GET /tasks/{id}
  tests/test_tasks.py# 기본 기능 pytest(TestClient)
  requirements.txt   # fastapi, pytest, httpx

지금은 완료 처리·상태 필터가 들어가기 전의 기본 버전입니다. 그 두 기능을 직접 더하는 것이 13~16장 종합 프로젝트의 과제입니다.

핵심 두 파일만 미리 살펴봅니다. 데이터 모델과 라우터입니다.

python
# models.py
from enum import Enum
from pydantic import BaseModel


class TaskStatus(str, Enum):
    todo = "todo"
    done = "done"


class Task(BaseModel):
    id: int
    title: str
    status: TaskStatus = TaskStatus.todo
python
# routers/tasks.py (발췌)
@router.get("", response_model=list[Task])
def list_tasks() -> list[Task]:
    return store.get_all_tasks()


@router.get("/{task_id}", response_model=Task)
def get_task(task_id: int) -> Task:
    task = store.get_task(task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="Task not found")
    return task

GitHub에 올려 원격(origin) 만들기

지금까지는 내 컴퓨터 안의 로컬 저장소만 만들었습니다. 그런데 9장에서 변경을 git push로 올리고 gh로 첫 PR을 만들려면, 이 저장소가 GitHub에도 있어야 합니다. 실무에서는 팀의 저장소를 git clone으로 받으면 원격(origin)이 자동으로 잡히지만, 이 책은 team-tasks-api를 실습용 폴더로 받았으므로 내 GitHub 계정에 올려 원격을 직접 만들어 둡니다. 한 번만 해 두면 됩니다.

먼저 GitHub CLI(gh, 깃허브 명령줄 도구)를 설치합니다(Windows 11은 winget, 또는 cli.github.com에서 설치 관리자).

powershell
winget install --id GitHub.cli

설치한 새 터미널에서 GitHub 계정으로 한 번 로그인합니다. 브라우저가 열리고 안내대로 인증하면 됩니다.

bash
gh auth login

이제 이 폴더를 내 GitHub 계정의 새 저장소로 올리고 원격 이름 origin으로 연결합니다. 아래 한 명령이 저장소 생성·origin 연결·첫 푸시까지 한 번에 처리합니다.

bash
gh repo create team-tasks-api --private --source=. --remote=origin --push

--source=.는 지금 폴더를 올린다는 뜻, --remote=origin은 원격 이름을 origin으로 둔다는 뜻, --push는 첫 푸시까지 한 번에 한다는 뜻입니다. 끝나면 원격이 연결됐는지 확인합니다.

bash
git remote -v
console
origin  https://github.com/<내-계정>/team-tasks-api.git (fetch)
origin  https://github.com/<내-계정>/team-tasks-api.git (push)

origin이 보이면 준비가 끝났습니다. 9장의 git push -u origin ...과 gh pr create가 이제 동작합니다.

왜 로컬 git 저장소 + GitHub 원격을 둘 다 준비하나 9~10장에서 변경을 브랜치·커밋(로컬)으로 쌓고, push·PR(원격)로 올리려면 둘 다 필요합니다. 지금 git init(로컬 저장소)과 gh repo create(GitHub 원격 origin)를 해 두면, 이후 각 장에서 만든 변경을 깔끔한 단위로 커밋해 첫 PR까지 올릴 수 있습니다. 앞으로 장마다 새 작업 브랜치를 만들어 실습하고, 끝나면 python -m pytest -q로 검증한 뒤 진행하세요.

12. 흔한 오류와 오개념

오개념 1: "Claude Code는 똑똑한 자동완성이다." 아닙니다. 자동완성은 커서 주변의 다음 몇 줄을 제안하고 멈추며, 파일을 직접 만들거나 명령을 실행하지 못합니다. Claude Code는 파일을 직접 생성·편집하고 명령을 실행하는 에이전트입니다. 8장 worked example에서 보았듯 hello.py를 만들고 python hello.py까지 스스로 실행해 결과를 보여 줍니다. "다음 줄 제안기"가 아니라 "옆자리 페어 프로그래머"로 이해해야 도구의 쓰임이 보입니다.

오개념 2: "구독을 결제했으니 어떻게 로그인하든 구독으로 쓰이겠지." 틀립니다. ANTHROPIC_API_KEY 환경 변수가 설정돼 있으면 Claude Code는 구독이 아니라 그 API 키를 우선 사용해 종량 과금이 발생합니다. 예전에 API 실습을 하며 키를 영구 환경 변수로 박아 둔 신입이 자기도 모르게 종량 과금을 쓰는 일이 흔합니다. 구독을 쓰려면 echo $env:ANTHROPIC_API_KEY로 키가 비어 있는지 확인하고, /status의 Login method가 subscription인지 눈으로 확인해야 합니다.

오개념 3: "터미널을 닫으면 대화가 사라진다." 아닙니다. Claude Code는 세션을 저장합니다. 같은 작업 폴더에서 claude --continue를 실행하면 가장 최근 대화의 맥락이 그대로 복원되고, claude --resume은 저장된 여러 세션 중 골라 재개합니다. 닫혔다고 처음부터 다시 설명할 필요가 없습니다. 단, 세션은 작업 폴더 기준으로 관리되므로, 재개하려면 그 작업을 하던 폴더에서 명령을 실행해야 합니다.

오개념 4: "claude든 claude -p든 그게 그거다." 다릅니다. claude는 대화가 누적되는 REPL을 열어 여러 턴에 걸쳐 함께 작업합니다. claude -p "질문"은 답 한 번을 출력하고 곧바로 종료하며 맥락을 이어가지 않습니다. 함께 코드를 만들고 고치는 작업에 -p를 쓰면 매번 맥락이 끊겨 비효율적입니다. 반대로 "폴더 요약 한 줄"처럼 한 번에 끝날 질의에 REPL을 여는 것도 번거롭습니다. 작업 성격에 맞게 고릅니다.

자주 막히는 설치·인증 문제

  • irm이 인식되지 않는다 → PowerShell이 아니라 CMD를 열었습니다. PowerShell을 다시 엽니다.
  • claude가 명령으로 인식되지 않는다 → 설치 직후 PATH가 갱신되지 않았습니다. 터미널을 새로 엽니다.
  • 브라우저 로그인이 열리지 않는다 → ANTHROPIC_API_KEY가 이미 설정돼 API 키 방식으로 넘어갔을 수 있습니다. 변수를 확인합니다.
  • Bash 명령이 어색하게 동작한다 → Git for Windows(Git Bash)를 설치하지 않았습니다.

이 장 요약

  • Claude Code는 터미널·IDE·웹에서 동작하는 에이전트형 코딩 CLI로, 파일을 직접 읽고 편집하고 실행하는 페어 프로그래머입니다.
  • Windows 11 설치는 PowerShell 네이티브 설치 관리자(irm https://claude.ai/install.ps1 | iex, 권장) 또는 npm(@anthropic-ai/claude-code) 입니다. Bash 도구를 위해 Git for Windows를 함께 둡니다.
  • 인증은 구독(Pro/Max) 과 API 키 두 갈래이며, ANTHROPIC_API_KEY가 있으면 API 키가 우선됩니다. 구독을 쓰려면 그 변수를 비워 두고, /status로 방식을 확인합니다.
  • claude(대화형 REPL)와 claude -p(1회성 실행)를 작업 성격에 맞게 고릅니다.
  • 세션은 저장되며 --continue(최근 바로 잇기)·--resume(목록에서 고르기)으로 맥락을 이어갑니다.
